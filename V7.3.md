# Red Point Church V7.3 — Real Backend Deployment Bridge

V7.3 turns the backend from a documented plan into a deployable Supabase project structure.

## What is now included
- `supabase/config.toml` with function JWT policy.
- Four deployable Edge Functions:
  - `register-device`
  - `submit-visitor`
  - `send-push`
  - `sync-youtube-sermons`
- Shared CORS and admin-auth helpers.
- A baseline migration in `supabase/migrations/20260903_000001_red_point_baseline.sql`.
- Production hardening migration in `20260903_000002_production_backend.sql`.
- `VISITOR_EMAIL_TO`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, and `YOUTUBE_API_KEY` are server secrets only.
- The mobile app continues to use only Supabase public/publishable configuration and function URLs.

## Deployment
Supabase's documented production workflow is to authenticate with the CLI, link the project, push database migrations, and deploy Edge Functions. See the official Supabase documentation before running production commands.

Typical sequence:

```powershell
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
npx supabase functions deploy --project-ref YOUR_PROJECT_REF
npx supabase secrets set VISITOR_EMAIL_TO=... RESEND_API_KEY=... RESEND_FROM_EMAIL=... YOUTUBE_API_KEY=... --project-ref YOUR_PROJECT_REF
```

Never commit real secrets or paste service-role keys into the Expo `.env` file.

## Admin bootstrap
1. Create the staff account under Supabase Authentication.
2. Copy its user UUID.
3. Insert that UUID into `public.admin_users`.
4. Sign into the app's Staff/Admin area.
5. Test publishing, visitor inbox, notifications, and YouTube sync.

## Important migration note
The baseline migration is intended for a new/controlled project. If your existing Supabase project was changed manually, run `npx supabase migration list` and reconcile history before `db push`. Supabase specifically recommends keeping remote schema changes under migration control.
