# Red Point Church V6.6 — Production Build Pipeline

V6.6 is the first release that treats production builds as a repeatable pipeline rather than a collection of manual commands.

## Before the first build

On Windows PowerShell, from the project folder:

```powershell
npm install
npx expo login
npx eas login
npm run verify:production
```

If `npx eas login` asks you to authenticate, use the same Expo account that owns the EAS project.

## Android phone test (recommended first)

Build an installable APK:

```powershell
npm run build:android:preview
```

When EAS finishes, open the build link on the Android phone and install the APK.

## iPhone test

For a real iPhone distribution build:

```powershell
npm run build:ios:production
```

EAS will require the appropriate Apple Developer credentials/signing setup. The resulting iOS build can then be distributed through the configured Apple distribution path (for example TestFlight).

## Production builds

```powershell
npm run build:android:production
npm run build:ios:production
```

## Submission

Only after human device testing passes:

```powershell
npm run submit:android
npm run submit:ios
```

## Release gate

Do not submit until all are true:

- [ ] `npm run verify:production` passes
- [ ] Android opens and loads real church content
- [ ] iPhone opens and loads real church content
- [ ] Events work
- [ ] Sermons work
- [ ] Search works
- [ ] Visitor form works
- [ ] Notifications route correctly
- [ ] Offline/recovery behaviour is acceptable
- [ ] Admin publishing has been tested
- [ ] Granny Test passes
- [ ] Church leadership has approved store listing/privacy information
