# Red Point Church V6.7 — Production Environment Gate

V6.7 makes the production hand-off explicit: the app must be connected to the real Red Point Church Supabase project and EAS project before a production build is treated as valid.

## Before building

1. Copy `.env.example` to `.env`.
2. Fill every `EXPO_PUBLIC_*` value with the real production configuration.
3. Do not put Supabase service-role keys, YouTube API keys, or other server secrets in `.env` for the mobile app.
4. Confirm the Supabase Edge Functions are deployed and their URLs match the project.
5. Confirm the EAS project ID is the real Red Point Church project.

## Verify

```text
npm install
npm run preflight
npm run release-check
npm run check:production-config
npm run typecheck
npx expo-doctor
```

`check:production-config` intentionally fails when `.env` is missing or still contains placeholders. This is a gate, not a runtime fallback.

## Build only after the gate passes

```text
npm run build:android:preview
npm run build:android:production
npm run build:ios:production
```

## Production rule

A build is not considered production-ready merely because the JavaScript bundle compiles. The real Supabase project, Edge Functions, notification credentials, media storage, YouTube sync secret, admin account and real-device tests must also be verified.
