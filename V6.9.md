# Red Point Church App V6.9 — Admin & Backend Production Setup

V6.9 prepares the Supabase production side for a controlled deployment.

## What changed

- Added a Supabase migration for a unique sermon YouTube URL, preventing duplicate imports.
- Added public/admin indexes for leadership and ministries.
- Added a server-only environment template: `.supabase.production.env.example`.
- Added `npm run check:backend-config` to verify backend secrets are present without printing values.
- Added `npm run deploy:backend` to link the Supabase project, apply migrations, deploy all four Edge Functions, and set server-only secrets.
- Real server secrets are explicitly excluded from Git.

## Backend deployment

1. Copy `.supabase.production.env.example` to `.supabase.production.env`.
2. Fill in the real values. Never paste these into `App.tsx`, `.env`, GitHub, or the mobile app:
   - `SUPABASE_PROJECT_REF`
   - `VISITOR_EMAIL_TO`
   - `RESEND_API_KEY`
   - `RESEND_FROM_EMAIL`
   - `YOUTUBE_API_KEY`
3. Run:

```powershell
npm run check:backend-config
npm run deploy:backend
```

The Supabase CLI may ask you to authenticate and may require the database password when linking/pushing migrations.

## Functions deployed

- `register-device`
- `send-push`
- `submit-visitor`
- `sync-youtube-sermons`

## Security boundary

The mobile `.env` contains only public client configuration and Edge Function URLs. Service-role keys, Resend keys, YouTube API keys and visitor email configuration remain server-side.

## Release gate

Backend deployment is not the same as device acceptance. After deployment:

1. Run `npm run verify:production`.
2. Build the Android preview APK.
3. Test on a real Android phone.
4. Test the iPhone build separately.
5. Submit only after visitor submission, notifications, YouTube sync, media upload, admin publishing and offline/recovery behavior have all been manually verified.
