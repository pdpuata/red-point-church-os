# Red Point Church App V7.0 — Production Launch Candidate

V7.0 is the production launch-candidate checkpoint. It does **not** claim that the Supabase project, EAS builds, TestFlight, Google Play, or production notification infrastructure have been deployed. Those require the church's real accounts and credentials.

## Launch sequence

1. Configure the production `.env` from `.env.example`.
2. Run `npm run check:production-config`.
3. Run `npm run backend:check`.
4. Deploy Supabase migrations in the order in `supabase/DEPLOYMENT_ORDER.md`.
5. Deploy the four Edge Functions and configure server secrets.
6. Create the first Supabase Auth admin and add its UUID to `admin_users`.
7. Confirm the `church-media` storage bucket is configured correctly.
8. Run `npm run verify:production` locally after installing dependencies.
9. Build Android preview and test on a physical Android phone.
10. Build iOS production/TestFlight and test on a physical iPhone.
11. Complete the Admin Release Check and the Granny Test.
12. Only then submit the production builds to the stores.

## Important security rule

Never put the Supabase service-role key, Resend API key, YouTube API key, or other server secrets in the Expo app or `EXPO_PUBLIC_*` variables. Public Expo variables are bundled into the mobile application.

## V7.0 exit criteria

- [ ] Real Supabase production project configured.
- [ ] All required migrations applied successfully.
- [ ] All four Edge Functions deployed.
- [ ] Required server secrets configured.
- [ ] Admin account created and tested.
- [ ] Media upload tested by an authorised admin.
- [ ] Visitor submission and email notification tested.
- [ ] YouTube sermon sync tested.
- [ ] Push notification registration/send/tap tested on iPhone and Android.
- [ ] Android preview tested on a physical device.
- [ ] iOS TestFlight build tested on a physical device.
- [ ] Offline/recovery behavior tested.

V7.0 is ready for store submission only when the real-world checks above are complete.
